# 坦克大战内置 AI 战术改造计划

## 目标与可行性

基于现有 React + TypeScript 项目重构四档内置 AI，新增 Lv.5「地狱使者」。现有会话、迷宫、发射规则、回合结算和 2～8 席入口可以继续用。新增部分集中在同源物理预测、风险评估、合法动作规划和对外观测字段。

Lv.5 定位为绝对终极 Boss。所有合法进攻机会都参与竞争，主动寻找隔墙激光、封走位和多方夹击中的反打窗口。取消故意犹豫和放水。对手未来操作无法预知，封死的局面也可能没有无伤动作，所以「零失误」以可复现的判题验收，例如避免推演内可避免的自伤、拒绝已经判定会被反弹击杀的开火，不能承诺任何实战都不死。

2～8 席均可上场。6～8 席同时选 Lv.5 时依然完整执行最高精度模型，反弹深度、候选集和安全审查不随人数、机器性能或帧率缩减。实时帧率和单步耗时在真实机器上测量，当前没有 0.5 ms 的依据。

| 已确定的产品选择 | 实现时采用的定义 |
| --- | --- |
| 全场信息 | 读取当前已经落地的坦克、墙、弹体、地雷、道具和可公开的状态，不接触未发生的掉落结果、随机种子流、对手指令或未来输入 |
| 物理公平 | AI 只提交现有五种动作的按下状态。发动攻击由引擎结算，使用同一套坦克速度、转向、炮口、弹夹、冷却、盾和道具时限 |
| Lv.5 五次反弹 | 飞行弹幕和射击规划跟踪最多五次墙面反弹及第五次之后的飞行段。按寿命、命中和武器本身的合法终止条件收束。提前完成近场避让评估后，保留远段到达时间用于战术规划 |
| Lv.5 激光 | 搜索五次反弹以内的主要攻击解，对实发角度按比赛规则完整追踪。规则允许六次及以上时，仍检查最后一段及后续合法段的首碰坦克、自伤和有效击杀 |
| 视觉与工坊 | 暗红深紫 Boss 标识，选人可见 Lv.5 与四项满格，交战中 HUD 保留身份。同步更新 Prompt MD 与可运行的参考模板 |

## 现状与直接原因

本节以当前源码为准。早期游戏设计文档里与源码有差异的数值，例如破片数量和寿命，AI 统一读取本场 `rules`。

| 位置 | 核对结果 |
| --- | --- |
| [botScripts.ts](../src/games/tank-battle/ai/botScripts.ts) | 内置角色每个固定步拿到 `TankWorldState`，历经选人、急避、缓存目标、开火门控。对手仅选一个，主要按欧氏距离和是否直视排序。最高档约每 0.045 秒重做战术，反弹搜索上限 2，采样 48 角，开火角度容差 0.085 rad。所谓全场感知目前只在几个独立分支里使用。 |
| [perception.ts](../src/games/tank-battle/ai/perception.ts) | 紧急避弹把飞行方向按直线外推，略过未解锁自伤的己方弹和当前隔墙弹，并把危险各自的垂线方向加权相加。夹击可能抵消，选出的方向可能卡墙。寻路是无权 BFS。射击预检是另一套简化墙面射线，自伤只看当前位置、指定距离内的反弹，直射分支只给 0 次反弹。 |
| [movement.ts](../src/games/tank-battle/simulation/movement.ts)、[world.ts](../src/games/tank-battle/simulation/world.ts) | 直觉模式同时控制屏幕八向移动和炮塔朝向。约 0.09 秒轻点窗口可以减少位移，但并非零位移，转向也受每步速度限制。实战在开火前先到期补弹、移动、解重叠并拾取道具。现有 AI 用移动前的角度和武器判断，随后又用瞄准方向覆盖原来的走位，能在同一步换出不同的炮口位置或武器。 |
| [weapons.ts](../src/games/tank-battle/combat/weapons.ts)、[projectiles.ts](../src/games/tank-battle/combat/projectiles.ts) | 实战有炮口贴墙即反射自伤、墙段胶囊扫掠、先命中的坦克、扇形散弹、碎片分裂、地雷隔墙和动弹抵消。AI 的直射/反弹解没有完整走这些分支。绕雷直接跳过了自己埋的雷。开火门控也未精确用下一步的 `fireReadyAt` 和点射上升沿，可能错过真正的射击机会。 |
| [sessionHost.ts](../src/platform/session/sessionHost.ts)、[aiSdk.ts](../src/games/tank-battle/ai/aiSdk.ts) | 内置策略同步运行并逐步合成输入边沿。工坊脚本经隔离 Worker 异步接收观测，当前每两步派发一次。SDK 已提供公开世界的精简信息，缺少完整的弹体到期、布防时刻、转向状态和武器规则等字段，模板不能直接套用内置 60 Hz 执行假设。 |

以上是代码路径核查。真实自伤频率、各档胜率及最慢帧从第一阶段的固定地图和种子对照取得。

## 1. 物理预测与实战同源

把当前实战的可复用计算提成纯函数。原实战调用点继续处理实体增删、音效、计分和回放。预测使用只读快照与局部副本，抢道具模拟保留同帧争抢的不确定性。

| 复用点 | 改造与校验 |
| --- | --- |
| 移动 | 在 `simulation/movement.ts` 抽出由四个方向键和一步 `dt` 求姿态的纯计算，保留持续按键、松键清零、轻点、前倒车速度、墙和坦克阻挡。多车挡位使用同帧可观测外推，本步最终射击要为未确定的阻挡和拾取留裕量。 |
| 飞行弹 | 复用 `simulation/collision.ts` 的 `sweepCircleAgainstMaze`、坦克和移动圆扫掠。共享炮口生成、反射法线、墙角合并、墙面偏移、同一步剩余飞行和自伤解锁。轨迹段记录起止点、实际模拟步、到达时间、半径、反弹序号和自伤区间。炮口立即反射也计入预测的五次。 |
| 激光 | 从 `combat/projectiles.ts` 的 `fireLaserRay` 中分离无副作用的几何计算，让实战与 AI 读取同一条折线及首个命中座位。使用实际激光半径、真实起点、首段忽略发射者和完整规则上限。盾消耗后光束仍在第一辆车终止。 |
| 破片、追踪、地雷 | 共享母弹到时分裂与碎片参数，默认 6 片、碎片独立寿命 3 秒，以本场规则为准。追踪弹沿当前路径与重算节拍分步积分，对手改道后重估。地雷以实战车尾位置、布防延迟、触发半径、伤害半径和隔墙判定预测，按所有座位检查触发，含埋雷者。 |
| 时序与抵消 | 先用现有步进顺序建立等价用例。当前普通弹抵消在弹体扫墙前独立处理，先把这一顺序录入基准。若验证出隔墙误消或同一步反弹后的相消偏差，单独确认物理修正及对照用例，再让两侧调用统一顺序。AI 的防守对消必须在当前规则开启且两颗都是普通弹时才可用。 |

开火审查用本步**预计移动及拾取后**的炮口、武器和弹量执行，依据 `world.battleTime + dt` 检查武器到期及冷却。普通与一次性道具提交可产生 `justPressed` 的边沿，连发每颗在实际到达冷却窗时重审。持有即将消失的道具或抢同一点时，按仍有道具和换到新武器两种可能验证。任何一条散弹弹道会击中自己且无退出方案时拒绝整次射击，护盾保护也进入时间判定。

## 2. 局势危险场、寻路与走位

1. **建立本步观测。** 保留所有存活对手的座位、朝向、近几步位移和道具，每回合清空旧历史，用对手可达范围约束速度外推。遍历所有弹体和地雷，包括当前隔墙、尚未布防、尚未解锁自伤的实体。按各自时间状态生成风险。对手的潜在枪线和已发射弹体分别计分。
2. **全场选可执行目标。** 在迷宫邻接表上给连边增加非负风险代价，用 Dijkstra 找移动或攻击路口。代价含到达时的弹幕、地雷和敌枪线、死胡同及连续暴露。道具按武器组合、存活概率、到达时间、剩余刷新时长和对手是否抢得到计分。高阶把同一目标的多条路线交给短时前瞻验证，寻找掩体、接近侧翼、主动拉回补弹。
3. **枚举输入并前瞻。** 直觉模式评估停驻及 8 合法方向，经典模式评估前进/倒车/静止搭配左转/右转/不转的 9 种组合。Lv.3 以上组合第一动作和后续短脉冲/释放/撤退动作，使用实际移动函数步进。Lv.5 在有限搜索树中评估多段动作，覆盖更远的走廊出口和多人包夹，持续重算并实际只提交当前一步。
4. **分层比较结果。** 首先淘汰在预测内有更安全替代的死亡路线。其次比较最小会遇时间、盾损耗、后续出口、与墙角距离、暴露时长与多方夹击。最后比较道具、攻击窗口、行进进度及重复转向。所有候选都危险时，选可验证的对消或最晚受击、能留盾或有退路的动作。
5. **处理卡墙和策略抖动。** 记录无效进展所在格、最近动作序列、最近得分差。方向易反复时使用动作保持奖励，危险升高时立即打断。卡住后枚举倒退或退回上一个通行节点、换边绕路，用预测位移与可达性评分，移除随机侧撞脱困。长期停驻记录为验证指标，安全且有收益的架枪可保留。

危险时间以战斗步为单位。未来弹道与候选轨迹要在同一个时间点对比，避免把已经飞过去的线当成墙，也避免被第四或第五次反弹返场的子弹包抄。路线级预测可以使用连续到达时间；临近碰撞、命中和点射必须回到真实固定步边界校验。

## 3. 瞄准和道具战术

- **直觉模式抓窗。** 对移动、短按方向和松键的候选序列求离散时间上的真实炮口角。安全走位优先。炮口经过可命中区间、该步预测姿态安全且具备有效开火边沿时射击，下一步继续掩体或脱离计划。当前档位允许的输入无法覆盖该角度时，换射击位置、改变转向序列或放弃开火。经典模式利用原地转向、正向和倒车组合执行相同的开火门控。
- **反弹解与封走位。** 同时考虑直射可达角与经墙反射的候选角。用镜像靶点、墙端与靶盘边缘构造候选，配合粗扫和局部细化避免只赌固定 48 个角度。每个候选都用同源轨迹验证，墙端的圆弧法线以实战结果为准。Lv.5 评估命中窗口、目标可逃出口、第三方枪线和己方撤退路径，预测对手常见转向、停驻、反打动作，优先选择能封安全出口或迫使目标离开掩体的射击。五次反弹覆盖用于扩大候选解，能用更短更安全的弹道击杀时优先短路线。
- **防御射击。** 有更安全的走位就留弹。来袭普通弹让可行路径都失效时，才尝试用真实普通开火抢对消点。必须验证实际出膛时刻、相对于双方墙碰和击中时间的事件顺序、两弹类型及抵消开关，也要复查第三颗弹。空弹、冷却中或手上是会替代普通攻击的道具时无此选项。

| 道具 | Lv.3～Lv.5 的策略方向 |
| --- | --- |
| 护盾 | 识别自身盾与破盾保护期，以盾换位争道具或近身。高阶同时估算敌方盾、跟枪和撤退机会，避免为了破盾把自己锁进弹道。 |
| 连发 | 抢有连发价值的狭路和出口，逐发确认安全与效果。留一发防身或提前停火换掩体，以实际剩余发数和到期时间决策。 |
| 散弹枪 | 评估所有弹丸的到达角度，近距离同时覆盖目标位置和两个逃跑方向。按 `shotgunPellets`、`shotgunAmmoCost`、张角和寿命验证。默认扇形同时三颗，整次扣两发，余弹不足保留弹药。 |
| 激光 | 先求可从掩体打出的多段折线，按照规则完整验证每个反射段与首碰坦克。能够隔墙首击或堵住对手瞬时换位窗口才释放。 |
| 追踪弹 | 评估从当前炮口释放到目标通道的安全性和拐弯代价。利用追踪弹把对手赶到自己能封住的出口。 |
| 破片弹 | 推演母弹到时的爆点和每颗碎片的反弹，选覆盖多个可行退路的爆点，并提前离开自伤区。 |
| 地雷 | 计算对手到必经口的时间和本车布雷后的撤离路线。达到布防时刻仍无法安全撤离则取消布放。已布的己雷可用于封路，也可被别人触发伤到自己。 |

## 4. 五档策略分层与 Boss 展示

所有难度共享武器安全底线。低档可以输在识别机会、前瞻深度和反应节奏，已判定贴墙返杀的开火应拒绝。下表反弹数是**战术搜索范围**，各档的自伤校验仍执行该武器的最低安全要求，例如激光必须按合法折线直到结束。

| 难度与现有 ID | 行为与能力范围 |
| --- | --- |
| Lv.1 新兵巡逻 `rookie` | 节奏平缓，直射为主，可保留有限犹豫。基本防贴墙自伤、己雷与简单撤离。 |
| Lv.2 战术游击 `tactical` | 直飞弹幕多方向避让，风险加权路径，近点道具和回掩体补弹。 |
| Lv.3 精英猎手 `elite` | 预判一次墙面反弹，利用掩体探头，寻找一次反弹射击，启用武器专项走位。 |
| Lv.4 噩梦反弹 `nightmare` | 预判两次弹幕反弹，评估多目标枪线，搜索 1～2 次反弹解，启用直觉抓窗与验证后的普通弹对消。 |
| Lv.5 地狱使者 `hellbringer` | 五次弹道攻防，无人为犹豫，全局多目标预测，连续控制出口，综合己方与敌方道具，完整激光路径。寻路、闪避、瞄准和道具四项均显示 `5/5`。 |

将 `BotModelDefinition.difficultyLevel` 扩至 5，常用默认 ID 继续为 `tactical`。四个旧 ID 保持可读，使用新的 `hellbringer` 注册 Boss。赛前详细选人、快速选人和乱斗座位可正常选择、保存和重载五档。Boss 主题使用集中定义的深紫底、暗红标识和清楚的「Lv.5 · 地狱使者」文字，高亮不占用玩家坦克颜色。当前四项属性上限本来为 5，按重构后的能力重新标定 Lv.1～4，确保 Boss 是唯一四项满格的档位。

在 `LobbyView.tsx`、`PlayerSetupPanel.tsx`、`ArenaRosterPanel.tsx` 复用同一款模型标识。对局由 `GameViewport.tsx` 根据稳定模型 ID 呈现 Boss 字样，结果与历史沿现有配置传递模型显示名。不要把 Boss 权限绑定到选手名字或颜色。随机阵容包含 Boss 的条件沿用阵容生成规则，在对应页面测试。

## 5. 高精度多人运行与预算

| 路径 | 执行约束 |
| --- | --- |
| 共享一次计算 | 同一个世界步只建一次只读索引与基础弹道，所有内置 AI 共用。用 `roundNumber`、实际战斗步和地图身份作为缓存边界。炮口、候选路径、目标变化产生的结果按几何输入精确失效。各席预测输入和评分各自计算。 |
| 优先节省重复扫描 | 用静态墙体索引和扫掠包围盒筛选墙段，保持原先的首碰顺序与并列法线。弹体空间桶只剔除不可能相交的候选。Dijkstra 复用阵列和同场迷宫连接。比较缓存开关前后的逐步动作与命中输出，结果一致才启用。 |
| 固定步整批提交 | 内置模型依然接受 60 Hz 同步世界步。先完成同一快照下各席结果，再提交同一步输入。性能不足先做等价索引、增量和批处理。若仍需迁移计算线程，应为内置策略单独设计带会话和步号的整帧协议，在输出到齐前控制模拟推进，暂停、结束或切换地图时丢弃过期结果。工坊当前的 30 Hz 最新动作缓存不适用于 Lv.5。 |
| 棋力优先 | 不设置动态步数截断、降反弹或拿旧步结果冒充当前结果。遇到超出参考机器预算时允许模拟推进变慢，实际游戏规则使用同一只战斗时钟，界面可显示正在计算。是否需要计算线程由前期性能数据判断。 |

基准同时记录逐席与整步 p50/p95/p99、AI 总耗时、物理/渲染耗时、决策间隔、墙碰查询量、GC 和实际帧/步率。覆盖 1v1、六席及八席 Lv.5、普通弹密集、追踪与破片同时在场、允许最大地图和高反射激光。记录硬件、浏览器、地图和规则。本机 60 Hz 每步总时长参考 16.67 ms，待基准建立后再给性能目标。添加每档候选数、反弹段数与超期结果计数，验证多人并未牺牲棋力。

## 6. AI 工坊联动

现有 SDK 标识为 `tank-battle-ai-v1`。保留现有字段、类型和 `createBot(ctx)` / `decide(obs, state, dt)` 两种入口。第一版为旧观测追加可选字段，说明扩展版本与缺省含义，必要时提供版本兼容入口。老脚本、保存的脚本记录和 Worker 限制按原入口验证。

- 在 `aiSdk.ts` 补充与真实模板同源的观测类型。公开本步身份、上一有效动作可选状态、己方 `moveHoldTime` 与实际 `fireReadyAt`、临时增益时限、盾与保护期、弹体寿命及分裂时刻、地雷布设与布防时刻、掉落过期时间。补齐实际墙段/厚度、弹体半径、追踪和各武器参数及普通弹抵消开关。对手字段采用当前对战可公开状态，与内置策略的公平边界一致。地图静态数据按现有 Worker 传输方式先验兼容，再优化重复传输。
- 在 `buildTankBattlePromptMarkdown` 同源生成字段定义、动作语义、时间基准和随规则变化的示例。说明工坊约 30 Hz 分发、回传异步、现有超时保护和单发按下边沿。要求模板同时适配经典及直觉两种模式，从全场状态找安全方向，对己雷、贴墙、散弹全扇区做审查，给出避弹、多目标和道具估值的写法及可达性限制。
- 更新 `DEFAULT_TANK_BOT_TEMPLATE_CODE`。示例保持自包含，读观测动态参数，保留合理复杂度与异步动作节奏。在注释中标明哪些预测是几何近似、哪些数据由宿主提供。公开策略示例使用共享物理输出时提供可序列化的公共字段，不暴露内置引擎对象或提升 Worker 权限。页面复制和下载 Prompt MD、载入模板、粘贴 JS/TS、试跑、保存和应用到乱斗都要验证。
- 120 步工坊校验继续验证接口和动作能运行。棋力对照另跑有反弹、拾取和交火的多回合，工坊界面不把一次短校验描述成战术验收。

## 8. 验收和对照方法

| 场景 | 完成条件 |
| --- | --- |
| 紧贴墙点射、直射打偏回弹、刚出膛的己弹反弹 | 可选安全动作存在时拒绝已知致死开火，并能在弹体仍未解锁时预测解锁后的回程。用普通弹、连发、散弹、破片、激光分别覆盖。 |
| 弹幕夹击、死胡同、己雷布防 | 斜向、后退、停驻或提前转出均纳入比较。可撤的案例选择生路。己雷未激活时预留撤离时间，隔墙安全按物理结果。 |
| 直觉微调与经典倒车 | 枪线在有效固定步过窗时才允许发射。检查「移动后撞墙」「移动一步刚拾道具」「一次性武器紧贴冷却上界」「上一帧持开火」。 |
| 专项道具与抵消 | 散弹每颗入模，破片爆点和碎片数与规则一致。普通弹抵消开启、关闭、被道具替代、隔墙或冷却不足分别覆盖。 |
| Lv.5 五次反弹 | 敌弹只在第 5 次反弹后进入可达路径时，AI 能提前反应。布置一次 5 反弹有效射击与一次第 5 段自身受击，验证选择和拒射。规则为六次反射时，实发激光最后一段仍参与自伤审查。 |
| 八席压力及复现 | 固定地图与种子、双方换位重跑。模拟指令、击杀和结果在相同输入下可复现。记录速度回退或物理暂停，逐席确认 5 次反弹和完整候选仍启用。 |
| 难度对照与胜率 | 建议用至少 30 组固定地图/种子，每组交换出生位，将新 Lv.4 对照旧 Lv.4、新 Lv.5 对照新 Lv.4。分别记录自伤/死亡、有效开火、无进展时长、回合结果、平局率和中位结束时间。首轮目标为新 Lv.4 的自伤比旧版下降至少一半，同时避免靠少开火或无限拖回合达标。Lv.5 对 Lv.4 胜率目标 70%（含平局折半计分），通过基准结果调整档位参数。 |

对局里保留简洁的可选调试信息，包括选择目标、拒火原因、最危险弹道、掩体路径和命中时间。验收看同一回放的预演与实际结果，尤其区分当前输入已经锁定的误判与对手临时改道。大厅 Boss 标识和仪表显示只用于辨识难度，棋力以可复现对局与战术判题确认。
