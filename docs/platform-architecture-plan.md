# 多游戏本地对战网站架构计划

首版支持两位玩家在同一台电脑进入大厅，选择坦克大战，设置资料、按键和规则，完成一场多回合比赛，查看结果并再来一场。未来火柴人对战通过同一套接入契约加入大厅。本文定义平台和游戏之间的职责。坦克数值、判定顺序与专属验收见[坦克大战计划](./tank-battle-plan.md)。

## 1. 技术与交付边界

| 选择 | 首版用途与取舍 |
| --- | --- |
| React + TypeScript | 实现大厅、设置表单、玩家状态栏、暂停层和结算页。用组件本地状态管理编辑过程，用类型约束游戏注册信息和平台事件。 |
| Vite | 提供开发入口、TypeScript 应用模板与静态资源构建。构建脚本显式执行 TypeScript 类型检查，再执行 Vite 构建。 |
| Canvas 2D | 绘制实时战场。游戏模拟使用独立的世界坐标，画布缩放只改变显示尺寸。 |
| 浏览器本地存储 | 保存玩家资料、各游戏改键与命名规则预设。刷新后恢复设置，再次开始时创建新比赛。 |
| 静态站点 | 首版本地双人同屏。大厅、游戏逻辑和地图生成都在浏览器运行，可以部署到普通静态站点托管环境。 |

交互以桌面键盘为基准。首页只展示已登记且可玩的游戏，初期只有坦克大战。账号、联机房间、手机控制和火柴人玩法留给对应版本另行设计。

## 2. 页面与操作流程

| 视图 | 用户操作 | 状态与去向 |
| --- | --- | --- |
| 游戏大厅 | 选择坦克大战，进入设置 | 读取注册表生成列表。进入设置时先选择对应游戏。 |
| 赛前配置 | 编辑玩家名、颜色、按键，选择或调整规则预设，开始比赛 | 标出同色、重复按键和无效参数。确认后的规则及玩家配置生成本场独立快照。 |
| 设置 | 编辑指定游戏的规则或改键，保存、载入命名规则预设，恢复默认 | 与赛前配置调用同一套表单、校验器和持久化接口。恢复默认作用于当前设置分组。 |
| 对战 | 同屏操作，查看各自状态，按 Esc 暂停 | 完整地图始终可见，地图外状态栏按玩家列表生成。暂停层提供继续与返回赛前配置的入口。 |
| 结算 | 查看最终比分，再来一场或回到赛前配置 | 再来一场重用已选玩家和规则，创建新会话、重置比分。地图按本场地图设置生成。 |

首版使用轻量视图导航，以大厅、赛前、设置、对战和结算作为明确状态。返回赛前或大厅时释放当前会话。比赛中的设置修改只影响新比赛。若从暂停层打开设置，返回对战前保持暂停，直到玩家明确继续。

## 3. 模块与依赖方向

| 规划位置 | 职责 |
| --- | --- |
| `src/app/` | 应用入口、游戏注册清单、页面导航、共享页面布局。这里将游戏定义注入平台。 |
| `src/platform/games/` | 游戏接入类型与注册表，按稳定的游戏 ID 查找定义。 |
| `src/platform/session/` | 会话宿主、模拟时钟、暂停及恢复、卸载和结算事件分发。 |
| `src/platform/input/` | 键盘采集、改键、跨玩家冲突校验、逻辑动作采样。 |
| `src/platform/settings/` | 配置草稿、字段表单、预设操作、本地存储与版本升级。 |
| `src/platform/ui/` | 玩家资料表单、状态栏框架、倒数与暂停层、比分及结算组件。 |
| `src/games/tank-battle/` | 坦克游戏定义、规则与默认值、地图、模拟、胜负判定、HUD 映射和 Canvas 绘制。 |

应用入口可以引用平台和游戏。具体游戏只依赖平台公开的类型与能力。平台组件通过已注册的定义访问游戏。即使将来火柴人也有跳跃、碰撞和血量，也要先由实际玩法验证复用价值，再提取公共模块。

以下是首轮开发的文件落点示例，目录随对应里程碑建立。

| 工作内容 | 建议文件 | 验证边界 |
| --- | --- | --- |
| 注册首款游戏、装配页面 | `src/app/gameCatalog.ts`、`src/app/App.tsx` | 新增游戏时在清单登记一次，大厅即可读取名称、人数和入口。 |
| 维护接入契约 | `src/platform/games/contracts.ts` | 平台对注册信息、会话和结果进行类型检查。这些类型可以在纯 TypeScript 环境引用。 |
| 采集与归一化输入 | `src/platform/input/keyboard.ts`、`src/platform/input/bindings.ts` | 同一步可表达两人同时移动与开火，改键后游戏仍然收到相同动作 ID。 |
| 驱动会话与挂载画布 | `src/platform/session/sessionHost.ts`、`src/platform/ui/GameViewport.tsx` | 前者驱动模拟与渲染，后者持有画布 DOM 引用，负责挂载与释放宿主。 |
| 编辑规则与保存预设 | `src/platform/settings/RulesForm.tsx`、`src/platform/settings/preferencesStore.ts` | 表单持有草稿，存储层负责序列化、校验、迁移与写入结果。 |

一次射击的数据流是 **物理按键 → 对应玩家的开火动作 → 坦克会话检查弹药与冷却 → 世界状态更新 → Canvas 绘制弹体、React HUD 更新弹量**。浏览器事件处理函数只记录动作。弹药扣除、弹体生成和比分修改分别在对应模拟步骤内发生。

## 4. 游戏接入契约

以下名字用于约定职责和接口语义，实现时可以按项目风格命名。

| 契约 | 谁提供 | 数据或操作 |
| --- | --- | --- |
| 游戏定义 | 游戏 | 稳定 ID、展示名、可玩人数、动作描述、默认按键、规则定义与默认值、完整规则校验、创建会话与渲染器的入口。坦克 ID 固定为 `tank-battle`。 |
| 玩家配置 | 平台 | 有序玩家列表，每项含稳定的玩家位 ID、显示名、颜色、本游戏的动作映射。比分、阵地和实体归属使用玩家位 ID 关联。 |
| 开局参数 | 平台交给游戏 | 经校验的玩家列表、规则版本及完整规则快照。地图编号等游戏参数随坦克规则传递。 |
| 输入帧 | 平台交给游戏 | 按玩家位和动作 ID 查询当步是否按住、是否刚按下或松开。游戏自行决定某动作采用哪种触发方式。 |
| 游戏会话 | 游戏 | 按固定步长推进，提供绘制所需的只读状态、HUD 信息和阶段事件。回合开始、回合结束与比赛结束由游戏裁定。 |
| 渲染器 | 游戏 | 接受画布尺寸和世界视图，绘制战场，可选用前后两个状态插值。渲染比例或设备像素比变化时更新画布映射。 |
| HUD 与结果 | 游戏交给平台 | 每位玩家的比分、状态项及可选剩余时间，回合事件携带存活或获胜玩家 ID。比赛结束事件携带最终比分和名次或并列结果。 |

平台决定状态栏的位置和通用表现，游戏决定状态内容与展示顺序。坦克提交「弹药、当前道具、道具可用次数、剩余时间」等字段，未来火柴人可提交自己的状态项。车身周围护盾、头顶名称和弹道光迹由坦克渲染器绘制。

## 5. 输入、时钟与会话生命周期

1. **准备。** 从本地存储加载记录，应用对应游戏的默认值与迁移，生成可编辑草稿。开始前校验人数、名称、颜色、按键和完整规则，随后复制成不可变快照。
2. **挂载。** 宿主创建一场会话、一个渲染器、一个输入上下文和一个动画循环。React 页面接收宿主通知，挂载清理与重建都释放旧实例。连续点击开始不能创建第二个活动循环。
3. **倒数与开战。** 会话在准备状态生成地图和出生点。倒数可推进自己的计时，到正式开战才开启移动、开火、补弹和道具刷新。平台根据会话阶段显示提示。
4. **推进。** 建议固定每秒 60 个模拟步，用单调时钟累积经过时间。每一步提交动作，游戏更新一次世界。屏幕每次刷新读取最新世界状态绘制。离散按键边沿只在首个适用的模拟步消费一次，持续按键则在后续步保持。碰撞、冷却与胜负只在模拟中判定。
5. **暂停。** Esc 由宿主处理。暂停时冻结模拟，清掉已按键和未消费动作，画面保留。建议窗口失焦或页面转入后台时自动暂停，重新聚焦后由玩家继续。恢复时重置动画时间基准，避免把离开期间的时间一次补进模拟。
6. **回合切换。** 游戏先完成同一步全部命中与淘汰结算，再发布带回合序号的结果事件。宿主显示游戏传来的比分和提示。游戏按规则决定进入下一回合或结束整场比赛。暂停回合间提示时也应冻结对应计时。
7. **退出。** 结束事件只消费一次。离开时停止动画循环，移除输入、窗口和画布监听，丢弃会话与暂存输入。新比赛重新创建实例。

改键建议使用物理键位标识 `KeyboardEvent.code`，界面另外显示易读键名。输入采集以游戏区聚焦或活动会话为前提，在表单中打字时按常规网页行为处理。在对战中拦截已映射方向键和空格的滚动。重复键盘事件不产生新的点按射击。改键录入使用独立输入模式，并保留 Esc 作为暂停或退出录入键。

React 更新只用于回合切换、比分、弹药、剩余次数和显示出来的时间值变化等 UI 事件。坦克位置、子弹与碎片每步都在游戏世界中更新，直接供 Canvas 读取。画布按可用区域等比缩放并适配设备像素比，避免拉伸迷宫或裁掉出生点。

## 6. 规则、预设与持久化

| 记录 | 键与粒度 | 保存内容 |
| --- | --- | --- |
| 玩家资料 | 全站，每个玩家位一份 | 名称、颜色。支持未命名时由玩家位显示 P1、P2 等默认名。 |
| 改键 | 游戏 ID + 玩家位 ID | 动作到物理键的映射。未来火柴人可有独立动作和按键。 |
| 当前规则 | 游戏 ID | 该游戏下次比赛使用的规则、规则版本。 |
| 命名预设 | 游戏 ID + 预设 ID | 名称及独立的完整规则副本，包括本游戏地图和道具设置。加载预设只替换规则草稿。 |

规则字段声明稳定键、分组、类型、默认值和适用的单位或取值范围，供通用表单生成控件。依赖其他字段的校验交给游戏，例如启用道具的权重、刷新间隔的上下界、迷宫空间与出生点约束。前端编辑和开局复验复用同一个完整校验器。

草稿与已保存值分开。编辑无效时显示到字段的原因。保存成功后再更新当前规则。新比赛使用完整快照，保存方案、更改名字或修改预设都不能反向改变已开局的状态。恢复默认和载入预设也要走同一条校验路径。

持久化记录包含格式版本。读取时逐记录迁移，并为新增字段补上默认值。损坏记录只影响对应分组，界面提示已使用默认值。存储不可用时使用当前会话内存设置，给出保存失败提示，玩家仍可开始本地对战。地图号与迷宫复现规则由坦克模块管理。

## 7. 实现规范与扩展

- Vite 的 TypeScript 转译与类型检查相互独立，项目构建入口应先运行匹配项目配置的 `tsc` 类型检查，再构建应用。[Vite 的 TypeScript 说明](https://vite.dev/guide/features.html#typescript)
- React 页面通过 `useEffect` 接入外部循环和事件时，清理函数须对称地注销监听并停止循环。开发模式下的 StrictMode 会额外执行一轮建立与清理，适合用来发现重复输入和未停止的动画。[React useEffect 文档](https://react.dev/reference/react/useEffect)
- 模拟层不依赖 React、DOM 或绘制 API。将经过时间、动作和地图生成参数作为输入。绘制与声音等表现消费模拟结果。
- 世界状态只有模拟层可以修改。HUD、画布和结算页共享同一判定来源，避免显示的倒计时与实际效果分别计时。
- 规则数值由游戏默认配置和本场快照取得。设置页展示的默认值要与模拟使用的值一致。
- TypeScript 开启 `strict`。存储读取结果视作 `unknown`，经版本迁移和校验后进入业务层。阶段与弹体类别使用可区分的联合类型，避免靠多组布尔量拼出互相冲突的状态。
- 世界坐标、画布像素和 CSS 像素在渲染边界换算。规则名标明单位，例如 `cooldownSeconds`。模拟层统一换算为步数或模拟时间，界面单独处理小数显示。
- React 页面负责编排，玩家卡、改键录入和规则字段控件按实际复用情况拆分。中文注释优先解释同帧结算、自伤解锁、版本迁移等有业务含义的边界。单文件接近 1000 行时按职责拆分。
- 玩家使用稳定 ID 和列表表示。双人限制只体现在首版游戏支持人数、赛前界面和当前玩法校验，判分、改键和资料读取均按列表处理。
- 后续增加火柴人时，新建游戏目录，登记动作、规则、模拟与渲染器。新增更多本地玩家时，优先扩展人数、可用出生点、改键冲突检查和 HUD 布局，并在真实键盘上验收多键同时按下。

## 8. 分阶段任务与验收

| 阶段 | 实现任务 | 完成条件 |
| --- | --- | --- |
| P1 平台骨架 | 建立 React、TypeScript、Vite 工程，搭建视图导航、注册表与游戏接入类型。 | 类型检查和生产构建通过。大厅可进入已注册的坦克赛前页。 |
| P2 配置与玩家 | 实现玩家资料、改键录入、冲突校验、通用规则表单、命名预设和迁移。 | 两页设置一致。冲突能定位。刷新恢复设置。切换规则预设保留名字和按键。 |
| P3 会话与输入 | 接通开局快照、画布宿主、固定步长、输入采样、暂停与卸载。 | 按住、点按和同时操作可区分。暂停和失焦不消耗比赛时间。反复开始与退出无重复输入。 |
| P4 首款游戏联调 | 接入坦克世界、道具、地图、HUD 与回合事件，贯通比分、结束和重开。 | 显示的弹药与效果同模拟一致。平局正确进入下一回合。返回赛前再开一场不会继承上场子弹或比分。 |
| P5 配置和交付验收 | 覆盖默认规则、自定义预设、按编号复玩地图、固定与随机出生点、暂停中改规则、不同窗口尺寸。 | 当前比赛快照保持有效，新比赛应用修改。整张地图始终可见。完成必要类型检查和构建，留下键盘手感与画面验收项供实际试玩。 |

坦克的地图与战斗实现可在 P1 确定接入契约后独立推进，P3 会话宿主就绪后进行第一轮可玩联调。火柴人对战在实际开始该游戏时，再以同一契约验证扩展性。
